## 4. 科学モデルの概要（v0.2.0基準）

実装済み：
- 解糖系10酵素
- LDHによる乳酸生成とNAD⁺再生、MCTによる乳酸排出
- ATP・ADP保存系、NAD⁺・NADH保存系
- HKのG6P阻害
- PFK-1のATP阻害とADPによる緩和
- PKのF1,6BPによるフィードフォワード活性化
- GLUTの可逆・飽和型促進拡散
- ATPaseによる細胞のエネルギー消費

未実装：AMP、アデニル酸キナーゼ、ミトコンドリア、酸化的リン酸化

### 設計原則
- 生物学的仕組みはプレイヤーが発見する前から存在する。研究は法則を有効にするのではなく、理解を可能にする。
- 単純化は許容するが、次を区別して可能な限り明示する：①実験的事実 ②事実に基づく近似 ③ゲームバランス用の仮想パラメータ ④未実装の生理学的機構
- ゲーム内の仮想単位を実際の濃度・反応速度と無条件に同一視しない。
- 保存則・非負性・平衡・数値安定性を重視。新反応の追加時は既存の物質収支への影響を必ず確認。ゲーム経済の調整で科学モデルの破綻を隠さない。

### 科学モデル変更時の記録ルール

科学モデルを変更する際は、次を記録する（記録先：CHANGELOGまたは設計書。場所は要確認）。

1. 反応式への影響
2. パラメータへの影響
3. 保存則への影響
4. ゲーム経済への影響

既存テストの期待値や判定条件を変更する場合は、**変更理由**と、**変更によって失われる検証範囲**を明示する。

## 5. 保存則とセーブ仕様

- セーブ内部バージョン：v7（データバージョン7）
- 旧セーブからv7への移行を実装済み（v0.2.0）
- `replaceSave`：バックアップ・本セーブの書き込み／検証失敗、復旧処理自体の失敗に対応。復旧不能時は画面上の進行状態を維持し、手動書き出しを案内。
- 制約：localStorageは複数キーの原子的更新ができないため、強制終了などあらゆる障害からの完全復旧は保証されない。この制約は今後も維持管理する。
- 炭素収支：`glcSupplied`と`glcReturned`は正味輸送量の符号で排他的に更新。検証では初期在庫・手動投与・外部取り込み・外部流出を一貫した定義で扱う。新しい輸送経路を追加する際も同様の検証が必要。

## 6. 直近の設計判断

- GLUTの逆向き輸送を、細分化した時間刻みと1秒刻みの両方で検証済み。
- 24時間延長試験でG6P約900.1 u、F6P約453.3 uに漸近。数値安定性は支持されるが、生理学的妥当性までは保証しない（既知の制約に記載の方針を維持）。
- 画面テストは`file://`を避け、HTTP(S)配信環境で実施。Chromium自体の不具合とは断定しない。
